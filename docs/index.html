moltdisk 蜕冗

    找出能重建的， 剩下的交给你

    moltdisk 走一遍你的项目，量出能从源码重建的产物——node_modules、target、dist、venv——排好序，并逐条告诉你凭什么这么判。然后它停下。这一版里没有删除代码。

    装上 读源码 看一条裁决是怎么得出的
    moltdisk 0.1.0~/code
    $ moltdisk ~/code
1.84 GB of build output can be rebuilt from source.

7 targets  ·  1.84 GB  ·  63.9k files
by kind: node 1.21 GB  ·  rust 512 MB  ·  python 96 MB

`moltdisk why <path>` shows the evidence for any entry.
This build never deletes — that call is yours.

    真实输出。终端里那句结论不是营销，是程序最后一个动作：报告交给谁，由谁决定删不删。

    01不删的理由

    早先的版本能删，所以我们把删除拿掉了

    早期内部构建确实会删。它带着护栏：目录名与同级标记必须同时命中——target/ 旁边得有 Cargo.toml，vendor/ 旁边得有 composer.json，Pods/ 旁边得有 Podfile；符号链接、家目录、给定根之外的路径一律拒绝。

    护栏是好的，但不够。一个凭启发式去删别人构建目录的工具，总有一天会删错；而按下回车的人，不会是写启发式的人。所以在公开之前，删除整段被移除了。

    留下的是本来最有意思的部分：判断，以及把判断摊开给人看。要删，请你自己删，用 moltdisk 递给你的清单。你懂你的项目，moltdisk 只懂它的规则册。

    自证
    no delete module
    no remove_dir_all
    -y → hard error
    symlinks refused
    $ moltdisk -y
moltdisk: this build
never deletes — `-y`
was removed in 0.1.0
    02裁决

    一条裁决要两样东西：名字，和标记

    名字不是证据。target/ 是个普通英文词，一个叫 target 但塞满源码的文件夹并不是构建产物。所以每条规则都要求：名字命中，并且同级存在只有真项目才会有的标记。点开任意一条，看它两半是怎么被逐项查过的。

    moltdisk why <path> 会把这两半原样打印出来，包括没找到时它到底在找什么。

    04边界

    它知道自己不明白什么

    • a

      符号链接既不跟随也不计入——扫描不会顺着一个链接走出给定根。

    • b

      默认深度 8。嵌在 node_modules 里的 node_modules 会跳过，数字不会算两遍。

    • c

      大小是文件的表观字节数，不是磁盘块占用。du 可能不同意，因为它量的是另一件事。

    • d

      monorepo 根上只有一个 lockfile，也仍然给每个 workspace 单独一条裁决，因为每个 node_modules 都是分开量的。

    05装上

    装一份，然后跑在你自己身上

    每个 Release 都附预编译二进制，每个压缩包配一份 .sha256。也可以从源码装：MSRV 1.80，只有一个依赖，没有 unsafe。

    预编译二进制

    • Linux x86_64musl static
    • Linux aarch64musl static
    • macOSIntel / Apple silicon
    • Windowsx86_64
    curl -LO https://github.com/yangyang2857-rgb/moltdisk/releases/download/v0.1.0/moltdisk-v0.1.0-x86_64-unknown-linux-musl.tar.gz
    全部版本与校验文件

    从源码

    cargo install --git https://github.com/yangyang2857-rgb/moltdisk
    # 然后
moltdisk ~/code
moltdisk why ~/code/web-shop/target
moltdisk kinds
